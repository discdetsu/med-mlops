Request path

Upload goes through Nginx to Django, which creates an inference_job and queues it in RabbitMQ. The worker runs cxr_core.preprocess, ONNX Runtime and CAM, then posts probabilities and the heatmap back through Django's internal API. Each prediction row stores model_version.

Training and promotion

A new DVC revision with at least N new labels starts a run; drift alone never does. The run registers @challenger with class thresholds and its drift reference. The gate compares it with @champion on the locked, patient-split test set using paired bootstrap CIs. After approval in Django admin, the alias moves and Django fans out the version; workers also ask Django at startup.

Monitoring loop

The monitor flow reads predictions and radiologist feedback per model version, compares embeddings and outputs with the champion's reference, and computes delayed AUROC from feedback. Drifted cases and model vs radiologist disagreements go to Label Studio. Pushgateway carries last_success, so a stalled flow raises an alert instead of showing old scores.

Running the demo

docker compose --profile core up starts the dot-marked services and seeds a starter @champion, so upload to heatmap works without training. --profile full adds Prefect, Label Studio and monitoring. CAM assumes a GAP + linear head, and the parity test runs a real DICOM end to end.
